# SEYED PREMIUM — نسخهٔ اصلاح‌شده

این بسته شامل ربات اصلی، موتور مستقل قیمت‌گذاری، محافظ دیتابیس و فایل‌های استقرار است.

## فایل‌های پروژه

- `bot.py` — منطق اصلی ربات و اتصال منوها، سفارش‌ها، پرداخت و مدیریت.
- `pricing_engine.py` — محاسبهٔ مرکزی قیمت Stars و Premium با `Decimal`، کنترل تازگی و الزام منبع تأمین‌کنندهٔ تأییدشده.
- `pricing_sources.py` — اعتبارسنجی ساختار کاتالوگ تأمین‌کننده، زمان منبع، واحد USDT و ادغام امن با دادهٔ مرجع.
- `database_safety.py` — انتقال غیرمخرب دیتابیس قدیمی و تهیهٔ نسخهٔ پشتیبان سازگار با SQLite WAL.
- `backup_manager.py` — زمان‌بندی بکاپ روزانه، تلاش مجدد پس از خطا و گزارش آخرین بکاپ.
- `health_monitor.py` — بررسی فقط‌خواندنی سلامت دیتابیس، زمان بکاپ و اعتبار مستقل نرخ/کاتالوگ؛ گزارش آن با دستور مدیریتی `/health` در دسترس است.
- `start.py` — راه‌اندازی با متغیر محیطی `BOT_TOKEN`.
- `requirements.txt` — وابستگی‌های سازگار با قابلیت‌های استفاده‌شده در کد.
- `render.yaml` — تنظیم Worker و دیسک پایدار برای دیتابیس و نسخه‌های پشتیبان محلی.
- `tests/` — تست‌های واحد موتور قیمت‌گذاری، اعتبارسنجی API، ایمنی دیتابیس، مدیر بکاپ و گزارش سلامت.
- `.gitignore` — جلوگیری از افزودن ناخواستهٔ دیتابیس، بکاپ‌ها و فایل‌های محرمانه به Git.
- `DEPLOY_CHECKLIST_FA.md` — چک‌لیست قبل و بعد از استقرار.

`stars_menu.py`، `service_menu.py` و `ui_config.py` برای حفظ سازگاری و ساختار قبلی در بسته نگه داشته شده‌اند؛ منطق فعال منوها در `bot.py` نیز وجود دارد.

## سیاست قیمت‌گذاری

- نرخ تتر و تلاش برای دریافت کاتالوگ هر ۶۰ دقیقه انجام می‌شود.
- قیمت قابل استفاده برای سفارش پس از ۶۰ دقیقه منقضی می‌شود. نرخ/قیمت قبلی فقط برای نمایش وضعیت آخرین دریافت نگه داشته می‌شود و بعد از انقضا قابل فروش نیست.
- سود پیش‌فرض ۳۰٪ و کارمزد پیش‌فرض ۰٪ است.
- تنظیم صریح مدیر که از قبل در دیتابیس ذخیره شده باشد، برای جلوگیری از تغییر ناخواسته حفظ می‌شود. در دیتابیس قبلی، مقدار کارمزد را در پنل مدیریت روی `0` قرار دهید تا دقیقاً با سیاست جدید شما یکی شود.
- کاتالوگ غیررسمی عمومی فقط مرجع است و برای ساخت مبلغ قابل پرداخت استفاده نمی‌شود.
- قیمت قابل فروش Stars/Premium باید از API تأمین‌کنندهٔ احراز‌شده، با واحد صریح `USDT`، زمان منبع معتبر و قیمت مثبت دریافت شود.
- اگر تأمین‌کننده قیمت یا زمان معتبر ندهد، خرید خودکار قیمت‌گذاری‌شده متوقف می‌شود؛ قیمت تخمینی یا منقضی جایگزین نمی‌شود.
- پلن‌های ۳، ۶ و ۱۲ ماههٔ Premium از قیمت‌های مستقل همان پلن‌ها استفاده می‌کنند.
- سایر محصولات مانند شماره مجازی، کانفیگ، بوست و خدمات شبکه‌های اجتماعی تا زمانی که API قیمت/هزینهٔ تأمین‌کنندهٔ معتبر برایشان متصل نشده، با قیمت دستی تنظیم‌شدهٔ مدیر کار می‌کنند؛ برای آن‌ها قیمت عمده‌فروشی ساختگی تولید نمی‌شود.
- محاسبهٔ نهایی با `Decimal` انجام و به تومان رو به بالا گرد می‌شود.

## راه‌اندازی

1. همهٔ فایل‌های این بسته را در ریشهٔ مخزن GitHub قرار دهید.
2. روی Render از Blueprint فایل `render.yaml` را همگام‌سازی کنید یا برای Worker دیسک پایدار با مسیر `/opt/render/project/src/data` اضافه کنید.
3. مطمئن شوید متغیر `BOT_TOKEN` در بخش Environment تنظیم شده است. توکن را داخل کد یا مخزن قرار ندهید.
4. متغیرهای `SHOP_DB_PATH` و `DB_BACKUP_DIR` باید با مسیر دیسک پایدار هماهنگ باشند. Blueprint این دو را تنظیم می‌کند.
5. Build command: `pip install -r requirements.txt`
6. Start command: `python start.py`
7. مدیر می‌تواند با دستور `/health` گزارش فقط‌خواندنی دیتابیس، بکاپ و اعتبار منابع قیمت را ببیند. این دستور فقط برای مدیر پاسخ می‌دهد.
8. مدیر باید کلید API واقعی تأمین‌کننده را در پنل قیمت‌گذاری ثبت کند. نمونهٔ پاسخ API باید دارای قیمت‌های USDT و زمان آخرین به‌روزرسانی باشد.
8. اگر دیتابیس قدیمی `shop.db` کنار `bot.py` وجود داشته باشد و مسیر دیسک پایدار هنوز دیتابیس نداشته باشد، در اولین شروع با SQLite Backup API به مسیر پایدار کپی می‌شود. فایل مبدأ پاک یا بازنویسی نمی‌شود.

## دیتابیس و پشتیبان

- برنامه `shop.db` را حذف یا بازسازی نمی‌کند.
- انتقال از مسیر قدیمی فقط وقتی انجام می‌شود که فایل مقصد هنوز وجود نداشته باشد.
- هر ۲۴ ساعت یک snapshot سازگار SQLite ساخته و ۷ نسخهٔ آخر در پوشهٔ `backups` نگهداری می‌شود.
- این بکاپ‌ها روی همان دیسک هستند و جای بکاپ خارج از هاست را نمی‌گیرند. برای بازیابی در خرابی کامل دیسک، نسخهٔ جداگانه در فضای ذخیره‌سازی مستقل لازم است.
- افزودن دیسک پایدار ممکن است هزینهٔ Render داشته باشد و در پلن/سرویس موجود باید در داشبورد قابل‌استفاده باشد.

## اجرای تست‌ها

```bash
python -m unittest discover -s tests -v
python -m py_compile bot.py start.py stars_menu.py service_menu.py ui_config.py pricing_engine.py pricing_sources.py database_safety.py backup_manager.py health_monitor.py
```

## محدودیت تأیید این بسته

در این محیط فایل `shop.db`، توکن ربات و کلید تأمین‌کننده موجود نبود. بنابراین تست زندهٔ Telegram، API تأمین‌کننده، اطلاعات واقعی مشتری/سفارش و بازیابی دیتابیس واقعی انجام نشده است. تست‌های محلی فقط صحت نحوی، منطق مستقل قیمت‌گذاری و انتقال/پشتیبان SQLite آزمایشی را بررسی می‌کنند. قبل از فروش واقعی، کلید API را در پنل امن وارد و یک سفارش آزمایشی واقعی با مبلغ کم، رسید و تأیید دستی مدیر انجام دهید.
